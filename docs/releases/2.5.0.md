# Code Space Release Notes - 2.5.0

## Overview

Code Space 2.5.0 adds an integrated terminal for desktop: a real PTY shell experience inside the editor and in full-screen terminal tabs, with an opt-in design where every network download is explicit. Terminals are organized in per-page groups, each with its own tab bar, and the embedded editor panel can hand a running terminal over to a new terminal tab without restarting it. Rendering follows your Obsidian theme with a WebGL renderer, and a CI workflow publishes verified prebuilt binaries for all supported platforms.

## New features

### Integrated terminal (desktop only)

Run a real system shell — PowerShell on Windows, zsh or bash on macOS and Linux — powered by xterm.js and node-pty.

- **Real PTY experience**: colors, interactive programs, job control, and paging behave like a native terminal (ConPTY on Windows, Unix pty elsewhere), with a dim notice line when a process exits
- **Terminal tabs with independent groups**: every terminal tab owns its own group of terminals with a full tab bar — click to switch, per-tab close, and a plus button to add terminals; closing a tab closes its group and reopening starts a fresh one
- **Embedded editor panel**: a resizable quick-terminal panel at the bottom of the code editor with its own group, plus a hand-over action that moves the terminal you are viewing into a new terminal tab with its process, scrollback, and output kept alive
- **Theme-aware rendering**: colors and the monospace font follow your Obsidian theme, including pop-out windows; a WebGL renderer keeps text sharp and scrolling smooth with automatic DOM-renderer fallback
- **Context-aware working directory**: new terminals start in the folder of the active file, resolving external mounts to their real on-disk location

### Opt-in enablement and explicit download

The terminal is disabled by default and every network action is user-initiated.

- Enabling the terminal toggle reveals the support-files section first; the shell, font size, scrollback, and session-cap settings appear only after the files are ready
- Terminal commands and the editor header button appear only when the terminal is enabled and ready, and they never download anything by themselves
- The prebuilt `node-pty` package (~1-3 MB per platform, SHA-256 verified) is downloaded only through the explicit **Download** button in settings, because the plugin store distributes JavaScript only
- Removing the support files is safe at any time: unlocked files are deleted immediately and files locked by the current session are removed automatically after Obsidian restarts

## Platform and developer notes

- Supported platforms: Windows x64/ARM64, macOS x64/ARM64, Linux x64 (`unzip` required for installation on Linux)
- A new CI workflow builds the platform binaries for a dedicated release tag, decoupled from plugin versions; re-running it safely overwrites assets
- Local terminal development is fully offline: `npm run pty:assets` builds the current platform's package, and the installer prefers a local dev source before falling back to the GitHub release
- The session cap is enforced across all terminal groups, evicting exited sessions from the current group first
