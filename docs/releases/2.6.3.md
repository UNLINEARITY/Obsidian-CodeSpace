# Code Space Release Notes - 2.6.3

## Overview

Code Space 2.6.3 lets you edit the code blocks inside your notes with the Code Space editor: place the cursor in a block, select the new button in the note header, and the code opens in a full editor window, then goes back into the note when you save. This release also lets you drag files into the terminal as ready-to-use paths, and fixes occasional garbled characters in the terminal.

## New features

### Edit note code blocks in Code Space

- With the cursor inside a fenced code block in a note, a code button appears in the note header, to the left of the reading/editing toggle. Selecting it opens the block in a Code Space editor window (issue #32).
- The same action is available as **Code Space: Edit code block in Code Space** in the command palette, which can be assigned a hotkey, and in the editor context menu.
- The window uses syntax highlighting for the block's language, including common names such as `python`, `javascript`, `shell`, and `c++`, and follows your font size, line number, and word wrap settings.
- Select **Save** or press `Ctrl/Cmd+S` to write the code back into the note. Closing the window also saves, and **Cancel** discards your changes. Saved changes can be undone in the note like any other edit.
- The opening fence line, including the language and any extra options, is kept unchanged. Code blocks inside callouts, quotes, and lists are supported, and their `>` markers and indentation are restored when saving.
- If the code block changed in the note while the window was open and can no longer be matched, Code Space does not overwrite anything. Your edits are copied to the clipboard instead.

### Drag files into the terminal as paths

- Drag files or folders from the Obsidian file list or from your system file manager onto a terminal to paste their real absolute paths. Files in external mounts resolve to their actual location on disk.
- Paths are quoted for the current shell (zsh, bash, PowerShell, or cmd), so names with spaces, quotes, or non-English characters work as is. Several files can be dragged at once.
- Paths are pasted, not executed, so you can keep typing the rest of the command.

## Bug fixes

### Terminal rendering

- Fixed occasional garbled or wrong characters in the terminal. The GPU renderer now matches the bundled terminal version, so the terminal correctly falls back to its standard renderer when the graphics context is lost, for example after sleep or a graphics switch on macOS.
- The terminal now rebuilds its glyph cache when it is shown again or its window regains focus, so characters drawn from a damaged cache are corrected automatically.

## Important notes

- Code block editing works in editing mode, including Live Preview. Reading mode has no cursor, so the button and command are not shown there.
- The READMEs in all seven languages now cover code block editing and dragging files into the terminal.
