# Code Space Release Notes - 2.6.2

## Overview

Code Space 2.6.2 speaks five more languages: the interface now follows Obsidian in Japanese, Korean, German, Spanish, and Brazilian Portuguese, and each language ships with a fully translated README. This release also adds a keyboard-friendly way to open additional terminal sessions, keeps your edits safe while files load or reload in the background, and makes external mounts far more predictable to remove and validate.

## New features

### Interface in five more languages

- The plugin interface is now available in Japanese, Korean, and German, plus Spanish and Brazilian Portuguese, alongside English and Simplified Chinese. The language follows your Obsidian interface language automatically, and regional variants such as Japanese (Japan) or German (Austria) are matched to their base language.
- Every language covers all 241 interface strings, and automated checks keep translations complete as the plugin evolves.
- The documentation now includes a full README translation for each of the five languages, reachable from the language switcher at the top of every README.

### New command: new terminal session

- The new **Code Space: New terminal session** command creates an additional session inside the focused terminal view or the embedded terminal panel, so opening extra shells no longer means one new Obsidian tab each (issue #34).
- The command respects the session limit, shows the same notice as the **+** button, and can be assigned a hotkey. When no terminal is open, it falls back to opening a terminal tab.

## Bug fixes

### Editor keeps your edits during file operations

- Edits typed while a file is still being decoded, or while an external change is being reloaded, are no longer overwritten by the result of that background read.
- Stale reload results are discarded after you switch files or close a view, so an older version of a file can no longer replace the one you are editing.
- Converting a file to UTF-8 now waits for pending decoding and saves, keeps the correct target file, and marks any edits made in the meantime as unsaved instead of losing them.
- When a remembered encoding applies, UTF-16 files keep their BOM on save, and reopening a file explicitly as UTF-8 now decodes it as UTF-8 instead of falling back to automatic detection.

### External mounts: reliable removal and stricter validation

- Mount entries whose link no longer matches the configured source can now always be removed from the list, with a notice explaining how to delete the remaining link manually. Previously such entries could become permanently stuck, and a single stuck mount could also keep the master switch from turning off.
- Mounting into hidden folders such as `.obsidian` or `.trash` is now rejected, along with Windows reserved device names, invalid characters, and trailing dots or spaces in mount path segments.
- On macOS, mounts whose source folder has been deleted can be unmounted again, including when the configured path differs only in letter case or sits behind a symlinked path such as `/var`.
- Mounting a network (UNC) folder with the junction link type now fails with a clear explanation instead of a raw system error, and a failed mount creation no longer leaves empty parent folders behind.
- The settings description and the READMEs now warn that cloud sync services may follow mount links and upload the mounted folder, with guidance to exclude mount folders from sync.

## Important notes

- Starting with this release, GitHub release pages begin with a preview banner of the plugin, added automatically by the release workflow.
- The automated test suite now runs on Windows in addition to Linux, so Windows-specific behavior such as directory junctions is continuously verified.
